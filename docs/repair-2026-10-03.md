# October 3, 2026 compatibility repair

This repair is being validated against one installed Windows build of
DRAGON BALL: Sparking! ZERO. Its executable SHA256 is
`e54e79e756f79719f09915078a37b6e87c23d32ecaaaa2f485d1a048ba198e55`.
The displayed version is **3020.019.003.012.013**. This is not a claim of
compatibility with the newer September patch or every current installation.

The source baseline is AccessForge/SparkingZeroAccess v1.0.1, commit
`c49ebebb4315d86d3749cb3f6fb6debca4fb6def`.

## Changes

- Unreal object reads now run on the game thread, with one pending dispatch.
  Map pre/post hooks suspend reads throughout loading and discard delayed reads
  from the old map. The previous duplicate-loop watchdog has been removed.
- Widget searches use the engine's widget query with the newer loader. Object
  lists are shared only within a polling cycle; displayed values remain live.
- Debug keybinds defer engine reads to the game thread. Team-caption reading
  avoids a nested asynchronous dispatch.
- Skill costs no longer pass Lua string substitution's second return value to
  `table.insert`.
- Image-based language values are read from the currently displayed texture.
  All 16 display languages and both voice languages are identified from native
  game data. See [language option research](language-options.md).
- Attached tutorial/menu text has an additional visible-tree reader, including
  hidden ancestors and active switcher pages. F6 reads the screen, F7 reviews
  the previous text, and F8 reviews the next text. These keys run on the game
  thread. Controls & Camera action names and key assignments were checked live.
- Windows key glyph 19 is Tab, as verified against the displayed Options
  shortcut. Adjacent glyphs are spoken separately. The controls diagram's
  `Pad_09` and `Pad_13` icons read as Left Stick and Right Stick.
- Hit areas can read their native `RemoteButton` display widget, with matching
  menu ownership and visibility checks. This avoids relying on equal numeric
  suffixes when a tutorial button and its caption have different names.
- Initially unready hit-area captions are retried briefly while focus stays
  still, then announced once when the game's native caption becomes available.
- Battle Training combines the current displayed lesson title, instructions,
  input glyphs and tip into one spoken/reviewable item. This does not access
  future lesson records. A live read of `OptionData.KeyIconTextTable` verified
  all D-pad/stick directions and exposed reversed menu/view mappings. D-pad Up
  also matches the player's confirmation against the captured Transform prompt.
- The installed OP3 opening has 19 descriptions in the user's recorded voice.
  Playback follows the actual visible movie's native frame clock and stops on
  skip, end or map change. See [movie description details](audio-description-design.md).

## Required loader configuration

The tested loader is official UE4SS `3.0.1-1152-ge3ba1016`, with archive SHA256
`AF8EA9D8975E8EFF7967423F43B8B50875E66A29A0F434CFFCE6E0867EA17252`.
Use its new layout: `dwmapi.dll` beside the shipping executable and `UE4SS.dll`,
settings, and Mods inside the `ue4ss` subfolder. Keep its SDK backend file and
license together with the loader. An active legacy root `UE4SS.dll` must be
backed up and disabled before using this layout.

Set `HookInitGameState=0`. Ghidra showed that the loader's detected target on
this executable returns a class pointer, while the hook expects an initializer.
The unmodified hook crashes even when the accessibility mod is disabled.
Disabling only this hook allowed the game and reader to start. Keep LoadMap,
EngineTick, BeginPlay, EndPlay, and script hooks enabled.

The other repair settings are `DefaultExecuteInGameThreadMethod=EngineTick`,
`bUseUObjectArrayCache=false`, `bForceGUObjectArrayForIteration=false`, disabled
Lua hot reload/automatic reload, and disabled loader GUI/console. The existing
upstream UTOC dependency and four speech DLLs are still required.

The original AccessForge installer currently selects the older loader. A source
update alone is insufficient for this tested installation; preserve the exact
loader and settings when deploying the repair.

## Validation status

The user confirmed startup speech and normal controls, including a normal
restart without a debugger. Reader polling averaged roughly 3 milliseconds
after startup, compared with 550–720 milliseconds using the original object
queries on the old loader. A repaired session also exited with code zero.

There are 175 Lua checks and five native audio checks, including scheduling,
cancellation of old-map reads, widget queries, focused and unfocused text,
language textures, movie timing and audio failures. All 19 opening descriptions
played in the game without skipped cues or backend errors and were detected in
process-only audio recordings. User feedback on voice/music balance is pending.
Controls & Camera and the Standard control-style overlay were checked live.
The candidate 11 native caption link was verified live on both Battle Training
top-menu rows, including Up/Down focus changes. The game links HitButton_0 to
CSG_BTN_01 and HitButton_1 to CSG_BTN_00; captions now follow those references.
The user's 21:26-21:35 session entered Transform training, opened the pause
menu, returned to the main menu and closed normally, with no logged reader or
audio errors. Offline replay of 84 training snapshots preserves all 539 captured
text rows and corrects 55 D-Pad Up prompts. These are log and regression checks;
the new lesson composition still needs listening verification. Image-only
training status, other lessons, battle HUD and new DLC character tables need
broader testing. The generic
reader can traverse all attached controls-list rows; exact viewport clipping
is not available when the game reports zero cached geometry.
